# MCP Flight Recorder 0.5.22

Version 0.5.22 adds a short installed demonstration and a practical investigation workflow while preserving the distinction between captured evidence and application correctness.

- Run `python -m mcp_flightrecorder.demo` or the equivalent isolated `uvx` command without an SDK, credentials or a provider. Four fresh synthetic recordings demonstrate faithful, mutated, incomplete and mixed evidence. The demo prints complete commands; generation success is separate from the intentional PASS, FAIL and UNKNOWN gate results. Both `fr` and `mcp-flightrecorder` invoke the same CLI.
- Use `gate --text` for bounded readable results from the same complete evaluation as JSON. Default answer scope remains `all`. Explicit `--answers mcp` excludes only independently validated, unambiguous local result-text comparisons and reports their count. Excluded local forwarding is not verified; malformed result identities fail, while missing selected results and ambiguous attempts stay unknown. Coverage, health, integrity and attribution requirements remain in force.
- Give the facade or proxy an existing directory or supported trailing directory separator to select a fresh recording file per start. The writer still reserves files atomically and preserves existing-file/sidecar conflicts. Optional proxy `--require-recording` requires successful recorder initialization before child launch; default startup remains fail-open, and strict startup does not guarantee later capture completeness.
- Browse a directory through ordinary CLI readers, then retain the disclosed absolute file and run ID for follow-ups. Plain unfiltered `turns --text` can show bounded MCP-only operations without inventing host turns. Existing JSON turn semantics and explicit-file MCP inspection remain unchanged.

The demo is synthetic controlled evidence, not proof of answer quality, a real integration or adoption. Metadata is not anonymization. The stdio proxy still requires POSIX pipes; alternate-separator handling does not establish native Windows qualification. Python 3.11+, SQLite schema 6, zero core runtime dependencies and the existing capture/inspection formats are preserved.

Follow the [installed demo](https://github.com/Steady-Hand-AI/mcp-flightrecorder/blob/0.5.22/README.md#install-and-record), [agent investigation workflow](https://github.com/Steady-Hand-AI/mcp-flightrecorder/blob/0.5.22/docs/agent-workflow.md), [SDK-free host example](https://github.com/Steady-Hand-AI/mcp-flightrecorder/blob/0.5.22/docs/easy-integration.md#complete-sdk-free-host-example), and [gate contract](https://github.com/Steady-Hand-AI/mcp-flightrecorder/blob/0.5.22/docs/inspection.md#evidence-gate). Earlier changes remain in the [0.5.21 release notes](https://github.com/Steady-Hand-AI/mcp-flightrecorder/blob/0.5.21/docs/release-notes.md) and [changelog](https://github.com/Steady-Hand-AI/mcp-flightrecorder/blob/0.5.22/CHANGELOG.md).
